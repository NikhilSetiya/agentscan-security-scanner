# AgentScan Deployment Scripts\n\nThis directory contains standardized deployment scripts for the AgentScan Security Scanner platform.\n\n## Scripts Overview\n\n### 🚀 deploy-production.sh\nThe main deployment script that supports multiple platforms and environments.\n\n**Usage:**\n```bash\n# Deploy to Kubernetes (default)\n./deploy-production.sh deploy --image-tag v1.2.3\n\n# Deploy to Docker\n./deploy-production.sh deploy --platform docker --image-tag v1.2.3\n\n# Deploy to DigitalOcean\n./deploy-production.sh deploy --platform digitalocean --environment staging\n\n# Dry run deployment\n./deploy-production.sh deploy --dry-run --verbose\n\n# Show deployment status\n./deploy-production.sh status\n\n# Run health checks\n./deploy-production.sh health\n```\n\n**Supported Platforms:**\n- `kubernetes` - Deploy to Kubernetes cluster\n- `docker` - Deploy using Docker Compose\n- `digitalocean` - Deploy to DigitalOcean App Platform\n\n**Key Features:**\n- Environment validation and prerequisite checks\n- Automated rollback on deployment failure\n- Comprehensive health checks\n- Support for dry-run mode\n- Detailed logging and error reporting\n\n### 🔄 rollback.sh\nComprehensive rollback and recovery script for all platforms.\n\n**Usage:**\n```bash\n# Rollback to previous version\n./rollback.sh rollback\n\n# Rollback to specific version\n./rollback.sh rollback v1.2.2\n\n# List available versions\n./rollback.sh list-versions\n\n# Emergency stop all services\n./rollback.sh emergency-stop\n\n# Create backup before changes\n./rollback.sh create-backup\n\n# Emergency restore from backup\n./rollback.sh emergency-restore backup-20241215-143022\n```\n\n**Key Features:**\n- Automatic backup creation before rollback\n- Platform-specific rollback strategies\n- Emergency stop and restore capabilities\n- Comprehensive health checks after rollback\n- Rollback validation and verification\n\n### ✅ validate-environment.sh\nEnvironment validation and prerequisite checking script.\n\n**Usage:**\n```bash\n# Validate environment for Kubernetes\n./validate-environment.sh --platform kubernetes --verbose\n\n# Validate and attempt to fix issues\n./validate-environment.sh --platform docker --fix\n\n# Validate staging environment\n./validate-environment.sh --environment staging\n```\n\n**Validation Checks:**\n- System prerequisites (tools, versions)\n- Environment variables\n- Configuration files\n- Network connectivity\n- Resource requirements\n\n## Environment Variables\n\n### Required Variables\n- `JWT_SECRET` - JWT signing secret\n- `SUPABASE_URL` - Supabase project URL\n- `SUPABASE_ANON_KEY` - Supabase anonymous key\n\n### Platform-Specific Variables\n\n#### Kubernetes\n- `KUBECONFIG` - Kubernetes config file path (optional if ~/.kube/config exists)\n\n#### DigitalOcean\n- `DO_TOKEN` - DigitalOcean API token\n\n#### Optional Variables\n- `GITHUB_CLIENT_ID` - GitHub OAuth client ID\n- `GITHUB_SECRET` - GitHub OAuth client secret\n- `AGENTSCAN_IMAGE_TAG` - Docker image tag to deploy\n- `DOCKER_REGISTRY` - Custom Docker registry URL\n\n## Prerequisites\n\n### Common Tools\n- `curl` - HTTP client\n- `jq` - JSON processor\n- `git` - Version control\n- `openssl` - Cryptographic toolkit\n\n### Platform-Specific Tools\n\n#### Kubernetes\n- `kubectl` - Kubernetes CLI\n- `helm` - Kubernetes package manager\n\n#### Docker\n- `docker` - Docker engine\n- `docker-compose` - Docker Compose\n\n#### DigitalOcean\n- `doctl` - DigitalOcean CLI\n\n## Configuration Files\n\nThe scripts expect configuration files in the following locations:\n\n### Kubernetes\n- `deployment/k8s/namespace.yaml`\n- `deployment/k8s/api-deployment.yaml`\n- `deployment/k8s/orchestrator-deployment.yaml`\n- `deployment/k8s/services.yaml`\n- `deployment/k8s/ingress.yaml`\n\n### Docker\n- `deployment/production/docker-compose.yml`\n- `deployment/production/Dockerfile`\n\n### DigitalOcean\n- `deployment/digitalocean/app.yaml`\n\n## Deployment Workflow\n\n1. **Validation** - Run environment validation\n   ```bash\n   ./validate-environment.sh --platform kubernetes --verbose\n   ```\n\n2. **Deployment** - Deploy the application\n   ```bash\n   ./deploy-production.sh deploy --image-tag v1.2.3\n   ```\n\n3. **Verification** - Check deployment status and health\n   ```bash\n   ./deploy-production.sh status\n   ./deploy-production.sh health\n   ```\n\n4. **Rollback** (if needed) - Rollback to previous version\n   ```bash\n   ./rollback.sh rollback\n   ```\n\n## Error Handling and Recovery\n\n### Automatic Rollback\nThe deployment script automatically rolls back on:\n- Deployment failures\n- Failed health checks (configurable)\n- Timeout conditions\n\n### Manual Recovery\n```bash\n# Emergency stop all services\n./rollback.sh emergency-stop\n\n# Create emergency backup\n./rollback.sh create-backup\n\n# Restore from backup\n./rollback.sh emergency-restore backup-name\n```\n\n### Backup Management\nBackups are automatically created in `deployment/backups/` and include:\n- Current deployment configurations\n- Service definitions\n- Configuration maps and secrets\n- Metadata with timestamps and versions\n\n## Monitoring and Logging\n\n### Health Check Endpoints\n- API: `/health` - Basic health check\n- API: `/ready` - Readiness check\n- Orchestrator: `/health` - Service health\n\n### Log Access\n```bash\n# View API logs\n./deploy-production.sh logs api 100\n\n# View orchestrator logs\n./deploy-production.sh logs orchestrator 50\n```\n\n## Security Considerations\n\n- All scripts validate prerequisites before execution\n- Sensitive environment variables are handled securely\n- Dry-run mode available for testing\n- Automatic backup creation before changes\n- Rollback capabilities for quick recovery\n\n## Troubleshooting\n\n### Common Issues\n\n1. **Missing Prerequisites**\n   ```bash\n   ./validate-environment.sh --fix\n   ```\n\n2. **Configuration Errors**\n   ```bash\n   ./deploy-production.sh validate\n   ```\n\n3. **Deployment Failures**\n   ```bash\n   ./rollback.sh rollback\n   ```\n\n4. **Health Check Failures**\n   ```bash\n   ./deploy-production.sh health --verbose\n   ```\n\n### Debug Mode\nEnable verbose logging for detailed troubleshooting:\n```bash\n./deploy-production.sh deploy --verbose --dry-run\n```\n\n## Contributing\n\nWhen modifying deployment scripts:\n1. Test in dry-run mode first\n2. Validate on all supported platforms\n3. Update documentation\n4. Test rollback procedures\n5. Verify health checks work correctly\n\n## Support\n\nFor deployment issues:\n1. Check the validation output\n2. Review deployment logs\n3. Verify configuration files\n4. Test network connectivity\n5. Check resource availability\n"
