# AgentScan Environment Configuration\n\nThis directory contains environment-specific configuration files for the AgentScan Security Scanner platform.\n\n## Directory Structure\n\n```\ndeployment/environments/\n├── production/\n│   ├── config.yaml          # Production configuration\n│   ├── secrets.yaml         # Production secrets (Vault references)\n│   └── .env.example         # Example environment variables\n├── staging/\n│   ├── config.yaml          # Staging configuration\n│   ├── secrets.yaml         # Staging secrets (Vault references)\n│   └── .env.example         # Example environment variables\n├── development/\n│   ├── config.yaml          # Development configuration\n│   └── .env.example         # Example environment variables\n└── README.md               # This file\n```\n\n## Environment Overview\n\n### Production Environment\n- **Purpose**: Live production deployment\n- **Security**: Maximum security settings, HTTPS enforced\n- **Performance**: Optimized for production workloads\n- **Monitoring**: Full monitoring and alerting enabled\n- **Secrets**: Managed through Supabase Vault\n\n### Staging Environment\n- **Purpose**: Pre-production testing and validation\n- **Security**: Production-like security with some relaxed settings for testing\n- **Performance**: Moderate resource allocation\n- **Monitoring**: Full monitoring enabled with team notifications\n- **Secrets**: Separate Supabase project/vault for isolation\n\n### Development Environment\n- **Purpose**: Local development and testing\n- **Security**: Relaxed security settings for development ease\n- **Performance**: Minimal resource requirements\n- **Monitoring**: Basic monitoring, text-based logging\n- **Secrets**: Local configuration, optional Supabase integration\n\n## Configuration Files\n\n### config.yaml\nMain configuration file containing:\n- Application settings (name, version, debug mode)\n- Server configuration (host, port, timeouts)\n- Database and Redis settings\n- Security configuration (CORS, rate limiting, headers)\n- Agent configuration (timeouts, enabled agents)\n- Monitoring and logging settings\n- Feature flags and performance tuning\n\n### secrets.yaml\nSecrets configuration file containing:\n- Kubernetes Secret definitions\n- Supabase Vault references (production/staging)\n- TLS certificate references\n- Docker registry credentials\n\n**Important**: This file contains references to secrets, not actual secret values.\n\n### .env Files\nEnvironment variable files for local development:\n- `.env.example` - Example file with placeholder values\n- `.env` - Actual environment variables (not committed to git)\n\n## Environment Variables\n\n### Required Variables\n\n| Variable | Description | Example |\n|----------|-------------|----------|\n| `DB_HOST` | Database host | `localhost` |\n| `DB_NAME` | Database name | `agentscan` |\n| `DB_USER` | Database user | `postgres` |\n| `DB_PASSWORD` | Database password | `secure_password` |\n| `REDIS_HOST` | Redis host | `localhost` |\n| `SUPABASE_URL` | Supabase project URL | `https://xxx.supabase.co` |\n| `SUPABASE_ANON_KEY` | Supabase anonymous key | `eyJhbGciOiJIUzI1NiIs...` |\n| `JWT_SECRET` | JWT signing secret | `your-super-secret-jwt-token` |\n\n### Optional Variables\n\n| Variable | Description | Default |\n|----------|-------------|----------|\n| `REDIS_PASSWORD` | Redis password | `` |\n| `GITHUB_CLIENT_ID` | GitHub OAuth client ID | `` |\n| `GITHUB_SECRET` | GitHub OAuth secret | `` |\n| `SMTP_HOST` | SMTP server host | `` |\n| `SMTP_USER` | SMTP username | `` |\n| `SMTP_PASSWORD` | SMTP password | `` |\n| `SLACK_WEBHOOK_URL` | Slack webhook URL | `` |\n\n## Secrets Management\n\n### Supabase Vault Integration\n\nProduction and staging environments use Supabase Vault for secure secret management:\n\n1. **Setup Supabase Vault**:\n   ```bash\n   # Set Supabase configuration\n   export SUPABASE_URL=\"https://your-project.supabase.co\"\n   export SUPABASE_SERVICE_ROLE_KEY=\"your-service-role-key\"\n   ```\n\n2. **Manage Secrets**:\n   ```bash\n   # List all secrets\n   ./deployment/scripts/manage-secrets.sh list --environment production\n   \n   # Set a secret\n   ./deployment/scripts/manage-secrets.sh set JWT_SECRET \"your-secret-value\"\n   \n   # Generate a random secret\n   ./deployment/scripts/manage-secrets.sh generate ENCRYPTION_KEY\n   \n   # Rotate an existing secret\n   ./deployment/scripts/manage-secrets.sh rotate JWT_SECRET\n   ```\n\n3. **Export/Import Secrets**:\n   ```bash\n   # Export secrets to .env file\n   ./deployment/scripts/manage-secrets.sh export\n   \n   # Import secrets from .env file\n   ./deployment/scripts/manage-secrets.sh import .env.production\n   ```\n\n### Local Development\n\nFor local development, create a `.env` file in the environment directory:\n\n```bash\n# Copy example file\ncp deployment/environments/development/.env.example deployment/environments/development/.env\n\n# Edit with your values\nvim deployment/environments/development/.env\n```\n\n## Configuration Validation\n\n### Validate Configuration\n```bash\n# Validate production configuration\n./deployment/scripts/validate-config.sh --environment production --verbose\n\n# Validate and attempt to fix issues\n./deployment/scripts/validate-config.sh --environment staging --fix\n\n# Skip connectivity checks\n./deployment/scripts/validate-config.sh --skip-connectivity\n```\n\n### Validation Checks\n- YAML syntax validation\n- Required configuration sections\n- Environment variable references\n- Secret availability\n- Network connectivity (optional)\n- Agent configuration\n\n## Environment-Specific Settings\n\n### Production Optimizations\n- SSL/TLS enforcement\n- Strict CORS policies\n- Rate limiting enabled\n- Compressed responses\n- Long cache TTL\n- Minimal logging\n- All security headers enabled\n\n### Staging Configurations\n- Relaxed CORS for testing\n- Team notifications enabled\n- Shorter cache TTL\n- Debug logging\n- All agents enabled for testing\n\n### Development Settings\n- CORS disabled for localhost\n- Rate limiting disabled\n- Cache disabled\n- Debug logging\n- Minimal agent set\n- Text-based logging\n\n## Security Best Practices\n\n### Secret Management\n1. **Never commit secrets to git**\n2. **Use Supabase Vault for production/staging**\n3. **Rotate secrets regularly**\n4. **Use strong, randomly generated secrets**\n5. **Limit secret access to necessary personnel**\n\n### Configuration Security\n1. **Validate all configuration files**\n2. **Use environment-specific settings**\n3. **Enable security headers in production**\n4. **Configure proper CORS policies**\n5. **Enable rate limiting and monitoring**\n\n### Access Control\n1. **Use separate Supabase projects for each environment**\n2. **Implement least-privilege access**\n3. **Monitor secret access and changes**\n4. **Use service accounts for automation**\n\n## Troubleshooting\n\n### Common Issues\n\n1. **Missing Environment Variables**\n   ```bash\n   # Check what's missing\n   ./deployment/scripts/validate-config.sh --environment production\n   \n   # Generate missing secrets\n   ./deployment/scripts/manage-secrets.sh generate JWT_SECRET\n   ```\n\n2. **Invalid Configuration**\n   ```bash\n   # Validate YAML syntax\n   ./deployment/scripts/validate-config.sh --environment production --verbose\n   ```\n\n3. **Connectivity Issues**\n   ```bash\n   # Test connectivity\n   ./deployment/scripts/validate-config.sh --environment production\n   \n   # Skip connectivity checks if needed\n   ./deployment/scripts/validate-config.sh --skip-connectivity\n   ```\n\n4. **Supabase Vault Issues**\n   ```bash\n   # Check Supabase configuration\n   echo $SUPABASE_URL\n   echo $SUPABASE_SERVICE_ROLE_KEY\n   \n   # Test vault connectivity\n   ./deployment/scripts/manage-secrets.sh list\n   ```\n\n### Debug Mode\n\nEnable verbose logging for detailed troubleshooting:\n```bash\n./deployment/scripts/validate-config.sh --verbose\n./deployment/scripts/manage-secrets.sh list --verbose\n```\n\n## Migration Guide\n\n### From Legacy Configuration\n\n1. **Backup existing configuration**:\n   ```bash\n   cp .env .env.backup\n   ```\n\n2. **Import existing secrets**:\n   ```bash\n   ./deployment/scripts/manage-secrets.sh import .env.backup\n   ```\n\n3. **Validate new configuration**:\n   ```bash\n   ./deployment/scripts/validate-config.sh --environment production\n   ```\n\n### Between Environments\n\n1. **Export from source environment**:\n   ```bash\n   ./deployment/scripts/manage-secrets.sh export --environment staging\n   ```\n\n2. **Import to target environment**:\n   ```bash\n   ./deployment/scripts/manage-secrets.sh import staging.env --environment production\n   ```\n\n## Contributing\n\nWhen adding new configuration:\n\n1. **Update all environment files**\n2. **Add validation to validate-config.sh**\n3. **Update documentation**\n4. **Test in all environments**\n5. **Update example files**\n\n## Support\n\nFor configuration issues:\n1. Check validation output\n2. Review environment-specific settings\n3. Verify secret availability\n4. Test connectivity\n5. Check Supabase Vault access\n"
